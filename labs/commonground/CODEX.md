# Задача для локального Codex

Проверь полный цикл CommonGround по `labs/commonground/README.md` в моём форке Moss. Moss уже запущен локально. Развивай этот стенд в отдельной ветке; сохрани незакоммиченные изменения и существующие профили.

1. Прочитай инструкции репозитория, README стенда и `cycle.json`. Уточни версии реально запущенного Moss и доступных инструментов. Выполни проверки Node и, если зависимости установлены, `yarn typecheck`.
2. Подготовь отдельный `../hrea-commonground-lab` через runner. Проверь наличие Nix; при необходимости следуй официальной инструкции hREA для моей ОС. Собери закреплённый выпуск, запусти UI на 8888 и upstream `demo-hrea`. Не обновляй conductor Moss для этого знакомства.
3. Выполни `test-hrea` с реальным conductor. Сохрани код завершения и вывод. При сбое сначала отдели ошибку сборки/схемы теста от ошибки экономического учёта. Найденную проблему воспроизведи минимальным тестом; не обходи проверку двух остатков передачей через фиктивные события.
4. Проверь в Moss группу, сообщения, потребность, участие, решение и задачи по таблице README, насколько эти действия доступны UI. Не выдавай созданные hREA API-записи за интеграцию с Moss. Если у тебя нет управления UI, выдай мне конкретные ручные шаги и отметь эту часть NOT RUN.
5. Если Unyt доступен, проверь прямой расчёт на 30 тестовых единиц и кредитный лимит. Остальные требования проверь отдельно либо отметь BLOCKED/NOT RUN. Не используй реальные средства. Не повторяй отправку платежа автоматически после неизвестного результата.
6. Запиши результаты в `labs/commonground/RESULTS.md`: PASS/FAIL/BLOCKED/NOT RUN, версии, шаги, фактические остатки и ID, ручные связи, ограничения UI, вывод по Moss/hREA/Unyt. Обнови эту ветку и draft PR; не сливай его автоматически.

Целевой результат — воспроизводимый опыт с честным отчётом. Прохождение одиночного API-теста не подтверждает P2P-синхронизацию, защиту от двойного расхода или готовность к реальному финансовому использованию.
